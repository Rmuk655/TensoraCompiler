# V0.3 research pitch (revised after P0)

Revised from the P0 spikes and capability matrix
([MATRIX.md](MATRIX.md)). Crisp. Final scope depends on the professor.

## What P0 established

- Ragged is real but **not open**: PyTorch jagged covers GPU dense-batch
  attention; CoRa covers ragged codegen; vLLM/llama.cpp cover
  KV-cache/GQA/CPU. Do not pitch "Tensora does ragged."
- Single-node scheduling has **little headroom**: Inductor is near the
  bandwidth ceiling and does not beat cuBLAS on GEMM.
- **Independence/reduction facts are NOT a gap.** A real ISL experiment
  (`tiramisu/islpy_ragged.py`) shows the polyhedral model *derives* them
  from the iteration domain (matmul dependence distances `(0,0,k)`).
- **Multiple ragged dims is not unique** either: TensorFlow RaggedTensor
  supports it, and TACO's level formats can encode nested structure.
- **The one cell that survives:** no system (TACO/Tiramisu/DISTAL/
  PyTorch) takes, as a *verified, typed, propagated* input, the
  **data-dependent iteration extent** carried today as side metadata --
  `lengths`, `cu_seqlens`, `padding_mask`, `position_ids`, `row_splits`.
  Polyhedral analysis needs affine bounds; a ragged extent `L[b]` is a
  runtime array, so it cannot be derived -- it must be given.

## The thesis (primary claim)

> **Compile-time verification and propagation of per-instance extent
> contracts through an ML graph.** Establish where `L[b]` comes from,
> prove its per-operator transfer `L' = f(L)`, and propagate it -- so the
> extent stops being untyped metadata the application maintains by hand.

Precise, and scoped against prior art:
- The extent *values* are runtime; the *relation* `L'=f(L)` is static.
- **Not** a new loop representation: MLIR already consumes a runtime
  bound (`affine.for %i=0 to %N`; islpy `[N]->{[i]:0<=i<N}`). The
  contribution is the high-level provenance/verification/propagation.
- **Not** first at size-dependent typing: Futhark does whole-array size
  types. The narrower claim is *per-instance* `L[b]` on a ragged axis,
  through an ML graph.
- **Not** independence/reduction (polyhedral derives those), not
  multi-ragged (TF/TACO have it), not "ragged in general".
- Scope limit: covers A/B/C operators (`extent/operator_taxonomy.py`);
  **not** data-dependent-extent D ops (nonzero/filter/MoE).
- Needs two contracts (`extent/contracts.py`): relational (static) +
  representation-consistency (runtime boundary check).

Routing to TACO/Tiramisu/DISTAL is a **second-stage** demonstration, not
the primary claim: first prove the extent contract is useful, then show a
backend consuming it. Leading with routing would be architectural, not
scientific. Full framing + falsification: [PROPOSAL.md](PROPOSAL.md).

## The concrete fact, grounded in real code

Programmers carry this extent by hand today. Real examples (from repo/doc
search):

- **wav2vec2 (speech)**: derives `input_lengths` from a mask, then
  `L_out = floor((L_in - K)/stride)+1` through each conv, rebuilds the
  mask. (fairseq `wav2vec2.py`)
- **LLM padding/KV continuation**: `position_ids =
  (attention_mask.cumsum(-1) - 1).clamp(min=0)`; a real Transformers
  issue shows wrong bookkeeping changes logits. (huggingface/transformers)
- **varlen attention**: build `cu_seqlens` from `seq_lens` for
  FlashAttention; vLLM/SGLang carry `seq_lens`/`prefix_lens`/`cu_seqlens`.
- **hierarchical NLP**: TensorFlow ragged docs use documents → paragraphs
  → sentences → words (multiple ragged dims).

In every case the extent is untyped side metadata threaded by hand.
Tensora's proposition: make it a verified typed fact and check its
propagation -- catching the exact bugs above, and giving a backend an
affine domain it otherwise cannot get.

## Routing tradeoff (answering "does feeding TACO lose cuBLAS?")

Yes. TACO and Tiramisu generate **their own** GPU code (TACO emits CUDA;
Tiramisu emits Halide → CUDA). Routing a region to them means their
kernel, **not** PyTorch's cuBLAS/cuDNN. So route to TACO/Tiramisu only
for the *structured/ragged* regions they specialize in, where a
hand-tuned dense kernel does not apply anyway; keep dense GEMM/attention
on PyTorch's kernels. Also note: Tiramisu takes its own scheduling DSL,
not MLIR, so "plug Tensora's MLIR into Tiramisu" needs a translation
step, not a direct feed.

## The concrete first experiment: verified extent propagation (wav2vec2)

Primary target: the surviving cell. Take the real wav2vec2 path (audio →
conv subsampling → transformer). The existing code carries
`padding_mask` + `input_lengths` + derived `output_lengths` by hand.
Tensora instead types the time axis with a verified extent `L[b]` and
propagates `L_out = floor((L_in - K)/stride)+1` through each conv.

Ablation (so the *verified extent*, not just "a new impl", is credited):

1. baseline: the real masked implementation;
2. Tensora **without** the extent contract (treats bounds as opaque);
3. Tensora **with** it (typed, propagated, verified);
4. inject a wrong length transform -> (3) must **reject** it at compile
   time; (2) and the baseline miss it (a real Transformers issue shows
   this class of bug changes outputs).

Measure: bugs caught, work eliminated (points inside the verified domain
vs padded box -- `tiramisu/islpy_ragged.py` shows ISL computes this
exactly), and whether the affine-per-instance domain lets a polyhedral
backend generate code it could not from the non-affine ragged form.

Secondary: two-ragged-dim representation (`pytorch_nested/ragged2d_spike.py`)
-- ragged x ragged pairwise, where the `[B, jA, jB]` output is not
representable in `torch.jagged` and padding wastes quadratically. Use it
as the representation stress test, not the headline.

## The verification angle (maybe demoable with current Tensora)

The cleaner research statement: existing compilers assume semantic facts
implicitly; Tensora makes them explicit and verified, so a transformation
that is otherwise illegal-to-assume becomes legal. Contracts:
`A independent of B`, `C is reduction`, `D equivalent to E`,
`length_i bounds the domain`. Experiment: a transformation (fusion,
loop reorder, communication elimination) that is unsafe without the
contract and legal with it, then measure. v0.1's semantic analyzer
already verifies axis contracts, so part of this may be demoable now --
worth checking before building anything new.
