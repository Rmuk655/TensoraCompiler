# V0.2 Closeout: Spikes and Honest Lessons

V0.2 was scoped small on purpose: not a build, but a set of spikes that
quick-check whether any future direction gives a real-world benefit
worth open-sourcing. This doc closes V0.2 with the results and the
decision.

The spike code and full numbers are in `research/ragged_spike/` on the
`v0.3-research` branch.

## What was spiked (all runnable, on an RTX 500 Ada 4 GB laptop GPU)

1. **Ragged attention** (`spike.py`) — padded vs PyTorch's own ragged
   path (`torch.nested`) vs a per-sequence loop.
2. **Ragged fused region** (`fused_spike.py`) — a whole custom region
   (attention → RMSNorm → Linear → GELU → Linear → residual): does
   PyTorch's ragged path break on it?
3. **Heterogeneity sweep** (`hetero_sweep.py`) — how the ragged gain
   tracks how uneven the batch is.
4. **Scheduling headroom** (`sched_spike.py`) — how close
   `torch.compile` (Inductor) is to the memory-bandwidth limit for
   pointwise, reduction, and fused kernels.
5. **Sharding communication** (`shard_analysis.py`, analytical) — does a
   semantic fact decide communication-free vs communication-heavy
   distribution?
6. **Coverage probe** (`coverage_spike.py`) — where does core PyTorch's
   ragged path actually break, across the untested cases, GPU and CPU?
7. **Distributed, measured** (`dist_spike.py`) — real gloo collectives
   across the 22 CPU cores: does a semantic fact predict a real
   all-reduce cost?
8. **Other systems' hypotheses** — TACO (`taco_hypothesis.py`, real
   `torch.sparse`), Tiramisu (`matmul_schedules.c`, native C schedules),
   and the compute-bound Inductor case (`gemm_spike.py`). Testing the
   hypothesis with a local proxy, not the system.
9. **Two-ragged-dim** (`ragged2d_spike.py`) and **randomized
   heterogeneity** (`hetero_random.py`) — the candidate missing row, and
   a rigorous sweep with confidence intervals.
10. **P0 capability matrix** (`MATRIX.md`) — the deliverable that
    locates the open cells.

Spikes are now organized by system under `research/ragged_spike/`
(`pytorch_nested/`, `distal/`, `taco/`, `tiramisu/`, `inductor/`).

## Lessons (honest)

- **Ragged is a real win, ~10-14x memory and ~8x speed** on a skewed
  batch. On the 4 GB GPU, padded attention runs out of memory where
  ragged fits.
- **Core PyTorch delivers it for GPU dense-batch attention.**
  `torch.nested` handled self/cross/causal attention, the fused
  attention→norm→FFN region, ragged pooling, autograd, and
  `torch.compile`. There a Tensora ragged pass adds nothing.
- **But core PyTorch BREAKS on the inference-serving path.** The
  coverage probe found KV-cache decode and GQA/MQA break on GPU nested,
  and CPU nested attention has no viable backend at all. These are not
  exotic — they are how real LLMs serve tokens. So "PyTorch captures
  ragged" is false for the cases that matter most for inference.
  Caveat: those exact gaps are already filled by specialized systems
  (vLLM / PagedAttention, llama.cpp), so the gap is in *core PyTorch*,
  not the ecosystem.
- **The ragged gain is regime-bound.** At fixed maxlen, eliminated work
  rises with skew (0% uniform → 73% extreme).
- **Inductor is near the practical ceiling single-node, both ways.**
  `torch.compile` reached 89-100% of the copy-bandwidth ceiling on
  bandwidth-bound kernels, and did not beat cuBLAS on a compute-bound
  GEMM (~20-28 TFLOP/s fp16). Little headroom on either.
- **The structure/schedule thesis holds in principle.** Sparse format
  gave up to 8.6x when sparse enough (TACO's premise); loop-schedule
  choice gave a 30x swing on the same matmul (Tiramisu's premise). These
  validate "structure and schedule are optimization information,"
  independent of ragged -- tested with local proxies, not the systems.
- **Making the ragged extent explicit changes correctness.** A padded
  mean-pool is silently wrong (by 0.647 on the test batch) unless the
  true length is known.
- **The one un-dominated direction is distributed, and it is now
  measured, not just modeled.** With real gloo collectives across the 22
  cores, sharding the reduction axis cost a measured ~11 ms/step
  all-reduce that sharding the independent axis avoided. The semantic
  fact (batch independent vs hidden reduction) predicts it. This is a
  lower bound vs a real network and CPU-only, and it does not test
  DISTAL the system -- but the hypothesis holds under measurement. A
  full result needs a real cluster; still research.
- **Verification is un-dominated too, but it is a checker, not a
  speedup.** Static named-axis / contract checking is something PyTorch
  does not do. V0.1's semantic analyzer already demonstrates this (see
  `demos/03_semantic_demo.sh`, which rejects an axis-name mismatch).

- **P0 matrix found two open cells** (`MATRIX.md`): static semantic
  verification (Tensora's only "yes"; no other system has it) and
  multiple independent ragged dimensions (PyTorch jagged cannot
  represent it -- tested; serving systems are single-ragged-axis). Every
  other capability is already covered by some system.

## Decision

- **No "faster than PyTorch" quick win.** Core PyTorch covers GPU
  dense-batch ragged and is near the bandwidth limit single-node. The
  gaps it does have (KV-cache, GQA, CPU/edge, distributed) are real but
  already filled by specialized systems (vLLM, llama.cpp). Do not
  open-source on a "faster than PyTorch" claim; any research pitch must
  be measured against those specialized baselines, not core PyTorch.
- **Open-source V0.1 as an academic teaching compiler.** That is its
  real, defensible value.
- **V0.3 candidate (research): Tensora as a verified semantic front-end
  that routes to backends** (TACO/Tiramisu/DISTAL/serving), targeting the
  two open cells. First fill the matrix `?` cells, then run the
  two-ragged-dim ablation. See
  [15_FUTURE_RESEARCH_DIRECTIONS.md](15_FUTURE_RESEARCH_DIRECTIONS.md)
  and `research/ragged_spike/V0.3_PITCH.md` (on the `v0.3-research` branch).

## Status

V0.2 is closed. The deliverable is the spike set plus these lessons, not
a shipped feature. This is the intended outcome of a "spike the future
directions" phase: a real, evidence-based answer, including the honest
negative results.
